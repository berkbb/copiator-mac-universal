# Development

## Requirements

- macOS 26 or later
- Xcode 26 or later (Swift 6.2+). The universal build needs full Xcode; the Command Line Tools are not enough.
- To rebuild rsync from its git tag: `autoconf` (`brew install autoconf`). Building from a release tarball (what the in-app updater does) needs only the Command Line Tools.

## Architecture

- **Process boundary:** Copiator never links rsync. It launches the unmodified `rsync` executable as a separate process (`CommandRunner`), which also keeps the GPL boundary simple.
- **Arguments:** `RsyncCommand` is the only place arguments are made. Default local copy: `-rltDhX --info=progress2 -i --partial`, macOS system folders excluded (`-i` is added to every copy without snapshots so the run's created items can be undone; it is left out for snapshot jobs and when only a batch file is written). Paths are absolute and come after `--` (names starting with `-` are not options; a name with `:` is not taken for a remote host because rsync only looks at a colon before the first `/`). "Copy its contents" adds a trailing `/` to the source. `--remove-source-files` is never produced (a `precondition` and tests guard this); `--delete` only when the job option is set, which the UI confirms.
  - "Keep permissions" adds `-pogA` (`-pog` when the engine has no ACL support).
  - exFAT, FAT and NTFS destinations (`FileSystemKind.lacksPosixMetadata`) never get `-p/-o/-g/-A`. FAT also gets `--modify-window=1` because it stores times in 2-second steps.
  - With extended attributes off, `-X` is dropped and `Quarantine.propagate` still copies `com.apple.quarantine` to the new items.
- **Progress:** `CommandRunner` streams stdout as records split on `\r` and `\n` and keeps only a 64 KB tail (`retainStdout: false`), so hours of progress lines never pile up. `RsyncProgressParser` reads `bytes pct rate eta (xfr#N, to-chk=a/b | ir-chk=a/b)`: bytes are 1000-based with `-h` (`29.70K`), rates 1024-based (`kB/s`), `??:??:??` means unknown. `ir-chk` sets `isEstimating`. `ProgressThrottle` sends at most four events a second.
- **Results:** `RsyncOutcome` maps exit codes (0, 20, 23, 24, 1/2/4, 3, 11/12/30/35…) and stderr to `JobResultKind`. Error classes are matched only at rsync's message position or as the trailing errno text, never anywhere in the line, so a file named `No space left on device (28).txt` or `chown notes.txt` cannot fake a class. On exFAT/FAT/NTFS, a 23 whose errors are all attribute warnings becomes `succeededWithNotes` with one info line.
- **Sandbox:** `SandboxProfile.forTransfer` allows writes only to the destination, then denies writes to the sources (SBPL: last match wins), so even `--delete` cannot touch a source inside the destination. Network, `mach-lookup` and `process-exec` (except rsync itself) are denied; local rsync forks and talks over a socketpair, which works under these rules. Personal-data folders are read-denied unless chosen as the source; when a source contains them (backing up the whole home folder), they are passed to rsync as anchored `--exclude` patterns instead of producing permission errors. Verify runs with no writable folder at all. Paths go through `realpath(3)` (`/private/var`). The sandbox fails closed: `CommandRunner.sandboxed(_:)` keeps the profile even when `/usr/bin/sandbox-exec` is missing, `CommandRunner.run` then throws `EngineError.sandboxUnavailable` instead of launching the program, and `RsyncEngine.run` and `compare` return `JobResultKind.sandboxUnavailable` before preparing anything. `SandboxProfile.launcher` is a task-local value so tests can simulate a missing launcher. Settings keeps the switch usable and warns while the launcher is missing; turning it off is the user's explicit choice.
- **Advanced options:** `CopyOptions.advanced` (`AdvancedOptions`) holds every rsync option that works inside the sandbox. All defaults produce no extra argument, so a default job runs exactly the original command. `AdvancedOptions.problems(source:)` validates patterns, `--chmod`, `--iconv`, suffixes, numbers, absolute paths and paths that would be written inside the source; the New Job sheet and `AppModel.addJob` refuse a job with problems, and the engine checks again. Filter order: sandbox-protected folders, system folders, then the user's `--filter`, `--include`, `--exclude`, `-F` and list files (first match wins, so a user include cannot re-include a protected folder). Verify passes only options that change the comparison (filters, `-H`, attribute flags, `--size-only`, `--modify-window`, reference directory, `--delete-excluded`). With openrsync, unsupported options are dropped and listed in the job log (`RsyncCommand.droppedOptions`). `RsyncCommand.displayString` shows the exact shell-quoted command in the New Job sheet and the inspector.
  - Extra sandbox paths per job: list files and the reference directory are readable; `--log-file` and `--write-batch` (file and `.sh`) are writable files; an outside `--backup-dir` and the `--link-dest` reference are writable folders. A hard link counts as a write to the existing file in macOS's sandbox (no narrower operation works), so `--link-dest` needs write access to the previous backup; `--compare-dest`/`--copy-dest` only read it.
  - rsync opens list files (`--files-from`, `--include-from`, `--exclude-from`) one path component at a time, so a list inside a protected folder cannot be read even with a file-level allow rule. `RsyncEngine.stageListFiles` copies the lists to a private 0700 temporary folder that is deleted after the run.
  - `--stop-at`/`--stop-after` make rsync print `stopping at requested limit` and exit 30; this becomes `JobResultKind.stoppedAtLimit`, the job is paused and resumable, and a stop time already in the past is ignored when resuming. `--preallocate` is not offered (this build reports "no prealloc"); `--read-batch` is a separate operation, not a copy option.
  - `RsyncOutputCollector` turns stdout records into model data: progress lines (per-file mode accumulates finished file sizes and takes the overall fraction from checked items), `--info=name1` names (current item), `flist2` counters (`isListing`, the job stays "scanning"), `-i` change lines (batched at most once a second, at most 500 per batch, delivered as one `TransferEvent.logBatch` so `jobs.json` is not written per file) and the `stats2` block (written to the log at the end).
- **Sleep and power:** `SleepGuard` takes a `PreventUserIdleSystemSleep` assertion (`caffeinate -i`) and, with "Keep the display awake", a `PreventUserIdleDisplaySleep` one (`caffeinate -d`). It verifies them in the system's per-process assertion list (`IOPMCopyAssertionsByProcess`, the source of `pmset -g assertions`) and checks they are gone after release. `AppModel` logs and announces the start (verified or not), the release (finish, pause, failure, quit) and power advice from `PowerAdvisor` (on battery, battery below 20 % / 10 %, Low Power Mode, lid, display), and re-reads the power state every 60 s during a job, announcing only new warnings and a reconnected adapter.
- **Snapshots:** with `CopyOptions.snapshots.enabled` the job's destination is a snapshot root. `SnapshotStore.prepare` reuses the newest `yyyy-MM-dd-HHmmss.partial` folder or creates one; `SnapshotStore.apply` points rsync at it and sets `--link-dest` to the newest complete snapshot (the user's own reference setting is ignored in this mode and `--delete` is not offered). The preflight counts the previous snapshot as already present. After a successful (or exit-23 partial, or not-verified) run the folder is renamed to a name that is always later than the newest existing one and `Latest` (a relative symlink, never replacing a real item) is moved atomically. Retention (`keepLast`, `keepDaily`, `keepWeekly`, `keepMonthly`; a snapshot stays if any rule keeps it, the newest always stays) runs only after a fully successful run and deletes only real folders whose names parse exactly as snapshot names; read-only folders in a snapshot are made writable inside that tree before removal. Verify and preview compare the source with the newest snapshot, or with an empty temporary folder before the first one.
- **Verify after copy:** `CopyOptions.verifyAfterCopy` (off, quick, checksum) runs `RsyncEngine.compare` inside the same run (status `verifying`, sleep assertion still held). Missing and changed items count as differences; extra items count only when `--delete` is on; attribute-only differences never count. Differences or an incomplete verification give `JobResultKind.verificationFailed` (the job fails, the first 100 differences are logged, a snapshot is still completed but no pruning happens).
- **Disks:** `VolumeWatcher` forwards `NSWorkspace` mount notifications to `AppModel`. A volume matches a job when the source or destination path is on its mount point (`/` never matches). `willUnmount`/`didUnmount` cancel the running job on that disk and mark it `suspendedForDisk` (also waiting jobs, and jobs that failed in the last 30 s, e.g. after a pulled cable); `didMount` requeues suspended jobs and re-runs finished or failed jobs that have `runWhenConnected`. `JobQueue.next` skips a waiting `runWhenConnected` job whose paths are missing instead of letting it fail.
- **Routines and rules:** a `Routine` has routes (source folder, `RuleGroup`, destination folder) and shared `CopyOptions`. Running it upserts one job per route (`TransferJob.routeID`): an idle job is updated and requeued, a waiting or running one is left alone, a missing one is created. `Routine.jobOptions(for:)` forces "copy contents", turns `--delete` off and puts the route's rules into `CopyOptions.rules`. At run time (and in verify/preview) `RsyncEngine.prepareRules` scans the source with `RuleScanner` (FileManager enumeration; packages count as one item; system folders and, under the sandbox, protected personal folders are not entered), evaluates `RuleEvaluator` (NFC-normalized names, case-insensitive text with Turkish I/ı/İ/i folded, regexes compiled once, any ancestor folder for "folder name", UTType conformance for kinds, depth limit 8; groups short-circuit). Advanced criteria read metadata lazily through `RuleItem`: size and dates from the enumeration attributes, "date added" and Finder tags from URL resource values, the hidden flag from `lstat` (`UF_HIDDEN`) or a leading dot, photo/video details prefetched by the scanner only when a media condition exists (ImageIO for images: pixel size, EXIF date, TIFF model; AVFoundation for audio/video: duration, video size, creation date, QuickTime model), and "contents" from one synchronous Spotlight `MDQuery` per condition scoped to the source (`kMDItemTextContent == "*text*"cd`). Spotlight folds case with the system locale (on a Turkish Mac the index holds "I" as "ı" and "İ" as "i"), so `Spotlight.query(for:)` searches every i-like letter as both "i" and "ı" (`||` of up to 64 variants; with more than six such letters, `&&` of the parts between them). Relative dates use the evaluator's `now` and calendar (the amount is clamped to 1,000,000 units so huge numbers cannot trap), so tests are deterministic. Regex conditions run with `.reportProgress`: ICU calls the block per start position and every few thousand backtracking steps (a count, not a clock), and after `RuleEvaluator.regexStepBudget` (5,000) calls the match stops, `runawayPattern` is set and `RuleScanner` throws `RuleEvaluator.RunawayRegex`; the engine logs `logRuleRegexTooComplex` and fails the job. Generated lists go to `EngineContext.scratchDirectory` (the user's temporary folder in the app; tests pass their own folder). The scanner then writes the matching relative paths to a private 0700 temp list passed as `--files-from` (NUL-separated with `--from0`; newline-separated for openrsync or when another `*-from` file is set, skipping names with line breaks). rsync then keeps the structure (`--files-from` implies `--relative`). The preflight counts only the selected files. The list is reused by verify-after-copy and deleted after the run.
- **Placement (route templates):** `RoutineRoute.placement` (`RoutePlacement`: folder template, keep structure, name template, date source, month-name language) becomes `CopyOptions.placement`. `RuleSelection.prepare` then builds a staging tree in the job's private scratch folder instead of a `--files-from` list (`PlacementStaging.build`): every selected file becomes an absolute symbolic link at its target path (`RoutePlacement.target`), with the source's extended attributes copied onto the link (rsync reads attributes from the link itself); packages are mirrored (real folders, file links, relative links that stay inside the package recreated, escaping links and selected symbolic links skipped and logged as `logPlacementLinksSkipped`); folders that exist in the source get its times. The job's source becomes the staging root and symlinks become `--copy-unsafe-links` (unless the user chose `-L`), so the conflict check, Keep Both (`singleFile` now carries the symlink flags), verification, quarantine propagation and resume run unchanged on target paths; the sandbox profile also gets the real source as a read-only source (`RsyncEngine.readSources`), and the preflight sums the real source files and the target counterparts. Template values pass `RoutePlacement.component` (no "/", ":" or control characters, leading dots and spaces trimmed until stable, 240 bytes); a staged path with "." or ".." is skipped. Dates: `PlacementDate.resolve` (date taken via `MediaInfo`, `TextDate.find` on the name or `ContentReader.text`, file dates).
- **Naming modes:** `RoutePlacement.renderName` drops the rendered text before or after a single `{name}` when the base name already starts or ends with it (case- and diacritic-insensitive). `{targetFolder}`/`{targetNumber}` come from `PlacementToken.addTarget`: in the folder template they describe the route's destination (plus the chosen folder), in the name template the deepest folder the file lands in; the number is the deepest `(digits)` match. `RoutePlacement.nameFixes` (`NameFix`: pattern, replacement) run after the template on the base name only when at least one has a pattern; `NameFix.pieces` parses `$n`, `${n}`, `${n:upper|lower|title}` and `$$`, conversions use the placement's language locale, and matching stops at `RuleEvaluator.regexStepBudget` (the name is then left unchanged). `problems()` reports invalid patterns (`invalidFix`) and unknown groups or conversions (`fixReplacement`). The result goes through `component()` again, so fixes cannot produce "/", ":" or leading dots.
- **Suggested placement ("ask for the folder"):** `RoutePlacement.askFolder` and `learnedFolders` (`PlacementMemory.key` → folder; the key is the folded words of the name without numbers and Turkish, English and Romanian month names, plus the lowercased extension). In `RuleSelection.prepare`, `PlacementQuestions.plan` takes each selected path's folder from `TransferJob.placementResolution` (skips included), then from a learned folder that still exists at the destination; the rest get up to 10 `FolderSuggester` candidates (name plus `ContentReader` text) and `PlacementQuestions.DecisionNeeded` is thrown. `RsyncEngine.run` turns it into `TransferEvent.placements(PlacementReport)` (at most 100 items, `total` counts all) and `.awaitingDecision` with `JobResult.placementsDetail` (so the job row and the notification say that folders are needed) before anything is copied; `TransferJob.pendingPlacements` makes `isAwaitingDecision` true. Preview and verify (`compare`) call `prepareRules(askFolders: false)` and use the first suggestion. `PlacementStaging.build(folders:)` passes the chosen folder to `RoutePlacement.target(folder:)`, which cleans it again and places the file there (keeping the source structure only with "keep structure") with the folder template below it. `JobQueue.finish` clears both fields on success and failure and keeps the resolution when paused. The app shows `PlacementDecisionView` inside `ConflictSheet` (so every "Decide…" entry point works); `AppModel.resolvePlacements` merges the resolution, requeues the job and writes remembered choices into the routine's route and the job's options. The AI only reorders suggestions (`Suggestions.rankFolders`, first 20 files), and `AILanguageWarning` is shown next to every AI control.
- **Content and destination criteria:** "text inside files" unions Spotlight's result with `ContentReader` (PDFKit for PDFs up to 50 pages, the first 1 MB of plain text in UTF-8 or Windows-1254; case, diacritics and Turkish I/ı/İ/i ignored) through `RuleItem.textContent`. "Copy with the same contents at the destination" (`RuleAttribute.inDestination`) builds a `DestinationIndex` of the job's destination only when a rule uses it: files grouped by size, SHA-256 compared only for same-size candidates and cached.
- **Routine on selected items:** `AppModel.runRoutine(_:on:)` groups the items by folder and queues one job per (folder, route) with `CopyOptions.selectedItems` (the scanner only looks at those top-level names), `routineID` set and no `routeID`, so the routine's own jobs are untouched. Entry points: the `sendToRoutine` Finder service (`RoutinePickerSheet`), `RunRoutineOnFilesIntent` and drops on sidebar routine rows.
- **Destination overview and folder suggestions:** `DestinationSummary.compute` (volume capacity, counts, size per first-level folder and the top five extensions; hidden files skipped) and `FolderSuggester` (Ratcliff/Obershelp similarity, Turkish folding, abbreviation and containment bonuses, content bonus, sibling enrichment; folders listed without hidden folders or package contents, at most 20,000).
- **Move to the Trash (opt-in):** `CopyOptions.trashSourceAfterCopy`. After a run that ends in success or partial success (never with snapshots, never after cancel), `SourceTrash.pairs` lists the copied files and their destination counterparts (rule selections with their placement targets, otherwise the whole source minus system and protected folders) and `SourceTrash.moveVerified` moves a source file only when the counterpart is a regular file with the same size and the same SHA-256. Moves go through `EngineContext.trashItem` (`FileManager.trashItem` in the app, a test folder in tests); emptied subfolders follow, the source root stays. `SourceTrash.archivedFiles` powers the clean-up sheet with a `DestinationIndex`.
- **Sync routines:** `Routine.kind == .sync` makes jobs of `JobKind.sync`, run by `SyncEngine`. `SyncPlanner.plan` scans both folders with the route's rules (`RuleScanner`, protected folders skipped), keys paths by NFC lowercased names, treats same size plus a time difference within 1 s (2 s on FAT) as the same file and otherwise compares SHA-256 for same-size files. Undecided differences reuse `ConflictReport` and `TransferJob.conflictResolution` (`ConflictDecision.reverse` = B wins; `ConflictPolicy.newer`/`.reverse` exist only for sync, `ConflictPolicy.choices(for:)`). Each direction is a plain `RsyncEngine` job with a private NUL-separated `--files-from` list, conflict policy replace and no delete; `.conflictsSettled` is not forwarded, so a resumed sync recomputes its plan.
- **On-device suggestions:** `Suggestions` talks to a `SuggestionModel`; the app uses `OnDeviceSuggestionModel` (`SystemLanguageModel.default`, behind `#if canImport(FoundationModels)`), tests use fakes. `rankFolders` sends at most 10 rule-based candidates and accepts only their numbers; `nameTemplate` sends up to 10 recent file names from the destination (`exampleNames`) and `cleanTemplate` strips quotes, brackets, prefixes and extensions and rejects unknown tokens or "/". `AppModel.canSuggestWithAI` requires the setting and an available model.
- **Local model servers:** `SuggestionProvider` (automatic, apple, ollama, lmStudio) and `AppSettings.aiProvider` (default automatic)/`aiOllamaModel`/`aiLMStudioModel`/`aiAutomaticOrder`/`aiAutomaticOff`. In automatic mode `AppModel.updateSuggestionModel` builds a `FallbackSuggestionModel` from `automaticProviders`; `Suggestions.ask` tries its available members in order and moves on when one throws (unreachable, timeout after 60 s, bad status) or its answer fails validation, records the member that answered (`lastSource`, shown as the source) and returns nil without an error when none answers. `AppModel.refreshLocalModels` polls only the servers that can be used (`LocalModelServer.models`: Ollama `/api/tags` without `remote_host`/`remote_model`/`…-cloud`/`…:cloud` entries and without models lacking `completion`; LM Studio `/v1/models` without embedding models), picks the first local model when none is chosen and rebuilds `suggestionModel` (`LocalServerSuggestionModel`, unavailable for unknown or cloud names). Requests (`LocalModelServer.request`) go to `http://127.0.0.1:<port>` through an ephemeral session with an empty proxy dictionary, no cache or cookies, a delegate that refuses redirects, and accept only 200 responses from 127.0.0.1 up to 4 MB; `<think>` blocks are removed. Info.plist sets `NSAllowsLocalNetworking`. `AppModel.localServerPorts` lets tests point at a fake server; the host never changes. Path suggestions: `Suggestions.folderTemplate` (examples from `exampleFolders`, validated by `cleanFolderTemplate`) and `Suggestions.placeFile` (candidate numbers or `NEW: path`, cleaned with `PlacementResolution.clean`; a new path that matches a candidate selects it).
- **Suggestion results and Apple tuning:** `Suggestions.rankFolders`, `placeFile`, `nameTemplate` and `folderTemplate` return `SuggestionResult` (`value`, `noSuggestion`, `unavailable`). `Suggestions.ask` runs one `Attempt` (`value`, `invalid`, `failed`) per available model; `reply` races the call against `Suggestions.timeout` (task-local, 90 s) with an unstructured task and a resume-once continuation, so a model that ignores cancellation is not awaited. Models with `choosesByName` (`OnDeviceSuggestionModel`) get `chooseByName`: the folders are offered as names through `choose` (guided generation with `DynamicGenerationSchema(anyOf:)`, greedy sampling), once in list order and once reversed, and the answer counts only when both agree; "(none of these)" leads to a separate new-folder question. Templates must pass `reproducesNames` / `reproducesFolders` (rendered with each example's date in Turkish, English or Romanian month names, `{name}` matching any text). `AIEvaluationTests` (`COPIATOR_AI_EVAL=1`) measures every local model on the same Turkish, English and Romanian questions.
- **Rule-based templates:** `TemplateInference` splits each example into letter, digit and separator tokens, finds its date (`TextDate`, else a four-digit year with a month name or an adjacent two-digit month, else the year alone) and turns the matching tokens into roles (`year`, `monthName`, `month`, `day`, `yy`); the common prefix and suffix across examples become the template and a differing middle becomes `{name}` (names only). When the examples differ in shape, the single largest group of at least two is used. `Suggestions.nameTemplate`/`folderTemplate` try it first (model optional) and `nameLanguage`/`folderLanguage` give the month-name language that reproduces the examples. `placeFile` runs `fits` (yes/no; guided for Apple) on a chosen existing folder unless `Suggestions.checksFit` is off (evaluation only). In a `FallbackSuggestionModel`, `ask` passes each attempt the next ready member; when Apple (`choosesByName`) picks an existing folder and that next model's `fits` says no, Apple's attempt counts as invalid and the next model decides (`crossChecks`, evaluation switch).
- **Turning AI on:** `AppSettings.aiSuggestions` defaults to false. The Settings toggle calls `AppModel.setAISuggestions`, which runs `checkAIPrerequisites` for `settings.activeProviders`: `AIPrerequisites.checkApple` (the `SystemLanguageModel.availability` reason, then a test question) and `checkServer` (server reachable, local chat models, chosen or first model present, test question within `testTimeout`). The setting is turned on only if at least one check is ready; `aiChecks` and `isCheckingAI` drive the result list and "Check Again". Tests inject `appleProblem`, `appleTestModel` and `localServerPorts`.
- **Backup reminder:** `BackupFreshness.stale` takes the jobs and routines whose destination is on the mounted volume (at launch: whose destination exists), skips `runWhenConnected` items and jobs that are running or waiting, and returns those whose last successful run (the newest `JobRun` whose result kind `isSuccess`; for a routine, the newest of its route jobs) is older than `AppSettings.backupReminderDays`; never-run items count from `createdAt`. `AppModel.remindStaleBackups` runs at the end of `volumeDidMount` and once in `launch()`, sends one notification and records `backupRemindedAt[id]`, so an item is reminded at most once a day.
- **Snapshot restore:** `SnapshotRestore` lists complete snapshots (newest first), maps the job's source into a snapshot with `TransferJob.target` (a source that no longer exists counts as a folder), lists a folder's items without following links, and groups a file's copies by `st_dev:st_ino`, so hard-linked unchanged copies are one version shown with the oldest snapshot. `restoreJob` builds an ordinary `.contents` copy job whose source is the item's folder in the snapshot and whose `selectedItems` is the item, with empty rules and `conflictPolicy = .ask`; `AppModel.restore` creates a missing original folder, queues the job and logs where it came from.
- **Archive integrity:** `ArchiveIntegrity.check` walks the destination's regular files (no links; `.DS_Store`, system folders and the list itself skipped; `skipDescendants()` only on directories, because on a file it skips the rest of the enclosing folder), hashes each inode once and compares with the previous `.copiator-integrity.json`. Same size and modification date with a different digest is corruption: the old entry is kept, so it is reported again until the file is fixed or legitimately changed. The list is written atomically after a full pass only (cancellation throws first). `RsyncCommand.exclusions` always adds `/.copiator-integrity.json`, which protects the list from `--delete` and keeps it out of verification. `AppModel.startIntegrityCheck` runs the check in a detached utility task with a `CancelFlag`; `integrityOnConnect` paths are queued in `volumeDidMount` (`pendingIntegrityChecks`) and started by `startDueIntegrityChecks` once `DiskEject.isBusy` finds no waiting, running or decision-waiting job on that volume (called after the mount and after every run, before `ejectIdleDisks`, so an eject waits for the check).
- **Repair:** `ArchiveIntegrity.repair` re-checks every reported path (still in the list, inside the destination with no "."/".." components and no parent that resolves outside it, same size and date, different digest), indexes candidate files of the needed sizes in the destination and in `repairSources` (sources of the jobs and routes whose destination is that folder; a single-file source counts), hashes each candidate inode once and takes the first with the recorded SHA-256. `write` opens the target with `O_NOFOLLOW`, writes in place (so hard-linked snapshot copies share the fix), truncates to the recorded size, `fsync`s, sets the modification time back with `futimens` and briefly adds the owner write bit to read-only files, restoring the mode afterwards; the target is hashed again before it counts as repaired. `AppModel.repairCorrupted` runs it detached with a `CancelFlag` and removes repaired and changed paths from the shown report.
- **Eject when done:** `CopyOptions.ejectWhenDone` (default false, tolerant decoding). After a run whose result `isSuccess`, `AppModel.finishRun` records the destination's volume (`DiskEject.volume`: not the root file system; ejectable, removable or not internal) and its sibling volumes (`DiskEject.siblingVolumes`: mounted volumes with the same DiskArbitration whole disk) in `pendingEjects`; `ejectIdleDisks` runs after every run, integrity check and repair and ejects a pending disk only when `DiskEject.isBusy` finds no waiting, active or decision-waiting job and no running check or repair on any of its volumes. `DiskEject.eject` calls `FileManager.unmountVolume` with `.allPartitionsAndEjectDisk` and `.withoutUI`; the result is logged on the job that asked and announced. `ejectTarget` and `ejectVolume` are injectable for tests.
- **Permissions:** `AppDelegate.applicationDidFinishLaunching` calls `AppModel.refreshPermissions(ask: true)` (bundle only): it requests notification permission when it was never asked (or granted without the badge), records `NotificationPermission` (`unavailable` when macOS refuses the request, which happens when the app is not opened from `/Applications`) and probes Full Disk Access with `FullDiskAccess.isGranted` (opens TCC.db, Safari, Suggestions and CoreSpotlight in the home folder; EPERM/EACCES means missing, nothing found means unknown). `applicationDidBecomeActive` repeats it with `ask: false`. While the permission is missing, `refreshFullDiskAccessNeed` (on every `save()`, `saveRoutines()` and permission change) checks job and route paths with `FullDiskAccess.isNeeded` (inside or covering `protectedLocations`, minus the sandbox's personal folders when the sandbox is on) and job results with `blockedRead`. `PermissionBanners` sits in the detail column's top safe area with a fixed height (title one line, detail two reserved lines, full text in the tooltip) and offers System Settings (`AppLinks.notificationSettings`, `FullDiskAccess.settingsURL`), Show in Finder when notifications are unavailable outside Applications, and Later (session only). When the need turns true while `isMainWindowVisible()` is false (the app is inactive or the main window is closed), `refreshFullDiskAccessNeed` posts one notification per launch. `PermissionStatusSection` (Settings › General) shows both statuses (`NotificationPermission.statusKey`, `fullDiskAccessStatusKey`) with the same buttons (`permissionButtonKey`) and re-reads them when shown. Purpose strings for the on-demand prompts are in `Info.plist` and every `InfoPlist.strings`.
- **Log (console):** `AppLog` (core, derived from the sister archiver app) keeps the last 2,000 entries in memory, appends tab-separated lines to `~/Library/Logs/Copiator/Copiator.log` (0600 in a 0700 folder, rotated once to `Copiator.1.log` at 1 MB, reread at launch) and mirrors to `os.Logger` with a public summary and a private detail; only the real app bundle writes the file and the unified log. `LogStore` batches refreshes on the main actor and filters by scope and search; `ConsoleView` is the table, detail pane and toolbar (copy, clear, Finder, Console). `AppModel` logs launch, engine probing, job start and end, disks, ejects, integrity checks, update failures, permissions, the battery hold, sleep and undo; summaries name jobs by `AppLog.short(id)` and never include paths.
- **Sleep when done:** `AppModel.sleepWhenQueueFinishes` (not saved) is checked by `considerSleepAfterQueue` after every run, integrity check and repair; `queueIsFinished` requires no running, waiting, active, undecided or disk-suspended job, no operation, integrity check or repair and no battery hold. The countdown task re-checks the queue every `sleepTick` and stops when work appears; at zero `sleepNow` turns the choice off and calls the injectable `sleeper` (`pmset sleepnow`; tests never sleep the Mac).
- **Undo last run:** `RsyncCommand.transfer` adds `-i` to non-snapshot copies (not with `logChanges`, which adds it anyway, nor with `--only-write-batch`); `RsyncOutputCollector` records `.missing` paths (up to `RunUndo.maxRecordedItems`) and counts `.changed`/`.extra` lines; the engine stores `RunUndo.Record` in `JobResult.undo` for successful runs and `JobQueue.finish` keeps it only on the last run. `AppModel.undoPlan` offers undo when the job is idle and the last run succeeded and was not undone; `RunUndo.undoCreated` rejects paths with empty, "." or ".." components or that resolve outside the destination, keeps items whose status-change time is older than the run (creation time cannot be used: rsync sets the source's modification time and macOS pulls the creation time back with it) or whose modification time is newer than the run, trashes files and then empty created folders deepest first; `RunUndo.undoSnapshot` trashes the newest snapshot only and repoints or removes `Latest`. `JobRun.undoneAt` blocks a second undo. Tests use a fake Trash (the app fixture now injects one for every model).
- **Time Machine exclusion:** `CopyOptions.excludeFromTimeMachine` (decoded as `false` from older records) makes `finishRun` call `keepOutOfTimeMachine` after a successful run; it sets `isExcludedFromBackup` on `TransferJob.timeMachineExclusionTarget` (the snapshot root, or the source's counterpart at the destination) every time, since `rsync -X` replaces the root's attributes, and logs only the first time or on failure.
- **Disk encryption:** `DiskSecurity.isEncrypted` reads `volumeIsEncrypted` from the nearest existing folder; `DestinationSummary.isEncrypted` carries it and `AppModel.volumeEncryption` (injectable) feeds `FillForecastView`; both show `UnencryptedDiskNote` only when the answer is `false`.
- **Battery hold:** `AppModel.batteryIsCritical` (setting on, `source == .battery`, below `PowerAdvisor.criticalBatteryPercent`) is checked in `refreshPower` while a job runs (`suspendRunningJobForBattery` cancels it like a disk suspension and records the id in `pausedForBattery`) and in `scheduleNext` before a job starts. `holdForBattery` sets `batteryHold` (which `scheduleNext` respects and the job list shows) and polls `powerProvider` every `powerCheckInterval` until the Mac is on AC or the setting is off; `releaseBatteryHold` requeues only the jobs paused for the battery that are still paused.
- **Fill forecast:** `AppModel.finishRun` stamps `destinationFreeBytes` (from the injectable `freeSpace`) on successful runs and finishes them at the injectable `clock()`. `FillForecast.estimate` keeps samples from the last 180 days, merges those within an hour, needs four over more than a day, turns consecutive pairs into bytes per day, and divides the latest free space by the 75th and 25th percentile rates (a non-positive slow rate leaves the upper end open; equal ends are widened by ±20 %). `AppModel.volumeKey` groups jobs by the destination's volume (or `/Volumes/Name` while unmounted); `warnIfFillingSoon` notifies at most once a week per disk through `fillWarnedAt`; `AppSettings.fillRange` formats the range with `DateComponentsFormatter` and always keeps two ends.
- **Diagnostic report:** `DiagnosticMasker` (core) turns the home folder into `~`, user names (and their parts of three letters or more) into `‹user›`, and every other path component into `‹name-xxxxxx›` from SHA-256 with a random per-report salt, keeping `keptNames`, snapshot names and short alphanumeric extensions. `text` masks known job paths first (longest first, so names with spaces go whole), then double, curly and guillemet quotes (not plain apostrophes, which Turkish suffixes use), then bare tokens that start with `/` or `~` after a space, quote, `(` or `=`. `argument` masks paths and hides `--include/--exclude/--filter/--suffix` patterns. `AppModel.diagnosticReport` (`Diagnostics.swift`) builds the text from `commandArguments(for:)`, `settings.log` and the permission states; `DiagnosticSheet` previews it and saves with `NSSavePanel`.
- **Low disk priority:** `AppSettings.lowPriorityIO` → `EngineContext.lowPriority` → `CommandRunner(lowPriority:)`, which sets `Process.qualityOfService = .background` before launch (macOS throttles the process's disk I/O and lowers its priority to 4); `sandboxed(_:)` keeps the flag, and exec through `sandbox-exec` and rsync's forks inherit the class. `RunnerTests` read the priority with `ps -o pri=` for a plain process, a sandboxed one and the rsync processes of a running job.
- **Move to another Mac:** `SetupTransfer` (core) writes `copiator-setup` version 1 with `PortableJob` (kind, source, destination, options) and a generic `Settings` payload; `read` checks size, then format and version from a small `Head` decode (so a newer file is explained even when the rest does not decode), and builds fresh `.paused` jobs. The app's `PortableSettings` (`MoveToMac.swift`) lists the exported settings explicitly; `withoutPaths` drops file paths and `stopAt` from the default advanced options on export and again on apply; `apply` skips unknown values. `AppModel.importSetup` runs the same validation as a new job (`importProblem`), appends through `appendImported` and never calls `scheduleNext`.
- **Snapshot search and compare:** `SnapshotSearch` walks each snapshot's content root (`SnapshotRestore.contentRoot`) with `lstat`, skipping hidden names and links. `search` folds names with `ContentReader.fold` and keeps at most `limit` paths (each with the snapshots that contain it, newest first); `compare` maps the older tree's regular files and compares size and `st_mtimespec` (seconds and nanoseconds) with the newer tree, so hard-linked copies are unchanged without a special case; lists are capped, counts are not. `SnapshotBrowserSheet` runs both through `runCancellable` (a detached task with a `CancelFlag` tied to the SwiftUI task), debounces the query by 300 ms and previews files with `.quickLookPreview`.
- **Open at login:** `LoginItem.swift` wraps `SMAppService.mainApp` behind `LoginItemService` (tests use a fake, the Mac's real login items are never touched). `LoginItemState` (`.notFound` counts as off: macOS returns it for a never-registered app, seen live on 2026-11-04) is read from the system in `refreshPermissions`, when the Settings row appears and after `setOpenAtLogin`, never stored in `UserDefaults`; a failed register or unregister shows an alert and the state stays as macOS reports it.
- **Notification buttons:** `notifier` takes an optional `NoticeAction` (`backUpNow([UUID])`, `showIntegrity(path)`, `decide(jobID)`), stored in the notification as a category and string user info. `AppDelegate.applicationWillFinishLaunching` registers the categories in the app's language and sets `NoticeHandler` as the notification center delegate (bundle only). `AppModel.handleNotice` runs the button's action and treats a click on the notification itself as "show" only; it ignores unknown jobs, jobs that no longer wait for a decision and folders that were never checked.
- **Duplicates:** `DuplicateFinder.groups` groups regular, non-empty, non-hidden files by size and then SHA-256, skipping second paths of the same inode and first-level snapshot folders (`SnapshotStore` names and `.partial`). `trashExtras` re-hashes the kept file and every extra just before calling the injected trash closure and skips anything that changed.
- **Routine transfer:** `RoutineTransfer.export` writes `{format: "copiator-routines", version: 1, exportedAt, routines}`; `read` refuses other formats, newer versions and files over 10 MB, gives every routine and route a new UUID, clears `lastRunAt`, and numbers names already in use (case-insensitive). `missingFolders`/`remap` let the import sheet point missing sources and destinations elsewhere before `AppModel.importRoutines` saves them.
- **Same-name files (conflicts):** `CopyOptions.conflictPolicy` (ask, replace, keepBoth, skip; default ask) and the one-time `TransferJob.conflictResolution` (per-path decisions plus a decision for "others"). Unless the policy is replace, `RsyncEngine.planConflicts` runs `RsyncCommand.conflictCheck` (`-n -ii`, without reference-directory options so `--link-dest` files do not look present) and `ConflictDetector` turns every existing file line into a `FileConflict` (identical when nothing would be transferred). A line rsync shows as new (`>f+++`, `cd+++`, `cL+++`) is also a conflict when `ConflictCollector` finds something of another type at that destination path with `lstat` (parent folders must be real folders; links are never followed): rsync would delete it silently. These carry `incomingFolder` for a folder; Keep Both renames the existing item to the next numbered name before the transfer (a failed rename excludes the folder instead). Only undecided conflicts are reported; `AppModel.resolveConflicts` merges the sheet's decisions into the earlier ones. Undecided conflicts emit `TransferEvent.conflicts` (at most 5,000 listed) and end the run with `JobResultKind.awaitingDecision` (the job pauses; the app shows `ConflictSheet` and notifies). Decided skip/keep-both paths go to a private `--exclude-from` list anchored at the transfer root (`RsyncCommand.escapePattern("/" + path)`: rsync treats a pattern as a wildcard pattern only when it contains `*`, `?` or `[`, and only then is `\` an escape, so the whole pattern is escaped once and only in that case; NUL-separated with `--from0`, which must precede the list options because rsync reads an exclude file when it parses the option); keep-both files are copied afterwards one by one with `RsyncCommand.singleFile` to `ConflictDetector.numberedName` ("name 2.ext", the next free number). `TransferEvent.conflictsSettled` marks the pass so a resumed run treats new same-name files (its own partial copies) as replace. Snapshots, `--ignore-existing` and `--only-write-batch` skip the check.
- **History:** `JobQueue.finish` appends a `JobRun` (start, finish, result with snapshot name and difference count, bytes, files) to `TransferJob.history`, capped at 100 runs.
- **Orphan guard:** `CommandRunner` registers every child with `ChildProcessGuard` (a fixed table readable from a signal handler, plus `running-processes.json` in the app). The app installs handlers for crash and termination signals that send SIGTERM to registered children and re-raise the signal. SIGKILL cannot be caught, so `AppModel.launch` first stops recorded processes whose start time matches exactly and whose parent is launchd, and logs it in the interrupted job.
- **Menu bar, Dock, Shortcuts:** `MenuBarExtra` (window style) shows the running job and pause/resume all; while it is shown the app does not quit when its last window closes. `DockProgress` puts a `DockTileView` on the Dock tile while a job runs: the app icon with a drawn green gradient bar (pale and full width while rsync is still counting) and a pill with the copy speed (`AppModel.runningSpeedText`), redrawn only when the shown values change; there is no number badge. A system `NSProgressIndicator` placed on the tile did not show in the Dock (hands-on round of 2026-11-04). Because an app registered for notifications only gets its drawn tile shown while its badge setting is on, notification permission is requested with `.badge` (`AppModel.notificationOptions`) and asked again at launch when it was granted earlier without it (`refreshPermissions(ask: true)`). App Intents live in the app target; SwiftPM emits the compiler's constant values (`*.swiftconstvalues`) and `Scripts/build_app.sh` turns them into `Contents/Resources/Metadata.appintents` with `xcrun appintentsmetadataprocessor` (Xcode does this step itself; SwiftPM does not). Titles are `Localizable.strings` keys; Siri phrases are in `AppShortcuts.strings`. `verify_bundle.sh` checks the actions and phrases are in the metadata.
- **Engine layer:** a job carries a `JobKind`; `TransferEngines.engine(for:)` returns the `TransferEngine` (today only `RsyncEngine`). Another engine is added as a new kind; queue, persistence and UI stay the same.
- **Queue:** `AppModel` runs one job at a time: the first `waiting` job in list order. Events travel through an `AsyncStream` and are applied in order on the main actor; the result is written only after all events. A started job switches to `scanning` immediately. Pause cancels the task (rsync gets SIGTERM, keeps the partial file, exits 20) and the job becomes `paused`; resume requeues it with the same command. While a job runs, an `IOPMAssertion` prevents idle sleep.
- **Persistence:** `JobStore` writes `~/Library/Application Support/Copiator/jobs.json` atomically. Decoding is tolerant (missing fields get defaults; unknown kinds, statuses or result kinds fall back). An unreadable file is renamed to `jobs.corrupt-<time>.json` and reported. On quit the running job is stopped and saved as interrupted; at launch it comes back paused (or waiting with "Resume interrupted jobs at launch").
- **Disk space:** before copying, the source size minus the matching data already at the destination must fit, leaving a reserve of 1 GB (at most 2 % of the volume, so small USB sticks stay usable). While copying, `DiskSpaceGuard` stops rsync when free space drops below 512 MB (half the reserve for small volumes); the job can be resumed after freeing space.
- **Engine selection:** candidates are the custom rsync (Settings), the bundled one, `~/Library/Application Support/Copiator/engine`, Homebrew and `/usr/bin/rsync`. A working custom rsync always wins; otherwise the newest full rsync wins, and macOS's openrsync (no `--info=progress2`, no `-X`/ACLs) is used only as a last resort in a limited mode.
  - openrsync starts its receiving side with `execvp("rsync")` even for local copies, so it gets `--rsync-path=<its own resolved path>` (`RsyncCommand.rsyncPathFlags`): the receiver is the same binary and the only program the sandbox lets it run.
  - It is never asked to copy extended attributes: `--extended-attributes` makes it write temporary AppleDouble files as `/private/tmp/.<pid>.<name>` and breaks dry runs. `Quarantine.propagate` still carries the quarantine flag; `-X` is listed in the job log as a dropped option.
  - Its `-i` codes are 9 columns wide and `*deleting` is not padded; `ItemizeParser.Format(engine:)` picks the right layout for verify, preview and the change log.

## Bundled rsync

`Scripts/build-rsync.sh` clones `RsyncProject/rsync` at `v3.5.1`, builds arm64 and x86_64 separately with `--disable-xxhash --disable-zstd --disable-lz4 --disable-openssl --disable-md2man --disable-idn --with-included-popt` (ACL, xattr and iconv on), joins them with `lipo -create`, checks with `otool -L` that only `/usr/lib` libraries are used, ad-hoc signs it and writes `Vendor/rsync/SOURCE.txt`.

- The git tag has no generated `configure.sh`; the script recreates `aclocal.m4` from rsync's own `m4/*.m4` (rsync does not use automake) and runs `autoconf`/`autoheader`. `.git` is removed before building so the version reads `3.5.1`, as in release tarballs.
- x86_64 is cross-configured (`--host=x86_64-apple-darwin`) with the arm64 run's cached test results, because macOS 27 may have no Rosetta to run x86_64 test programs.
- The binary built from the git tag and the one built from the release tarball are byte-identical (same SHA-256).

## rsync update flow

`update-rsync.sh` picks its target like the app expects:

| Run from | Updated |
| --- | --- |
| The project (`Scripts/`) | `Vendor/rsync/` |
| Inside the app (`Copiator.app/Contents/Resources/`) | That app's `Contents/MacOS/rsync`; the bundle is then ad-hoc re-signed |
| The app bundle is not writable | `~/Library/Application Support/Copiator/engine/` |
| `--dest` / `--app` given | The given targets |

Steps: GitHub release check (`RsyncProject/rsync`, drafts and pre-releases ignored) → download `rsync-X.Y.Z.tar.gz` → compare with GitHub's SHA-256 digest → `build-rsync.sh --tarball` → Mach-O and `--version` check → copy under a temporary name, then move into place. Without the Command Line Tools it stops with `ERROR=command-line-tools-missing`, which the app shows as a clear message.

### Chaos and security matrix

`Tests/CopiatorCoreTests/ChaosAndSecurityMatrixTests.swift` (29 cases) and `Tests/CopiatorAppTests/ChaosAndLoadAppTests.swift` (3) run in every `swift test`. Disciplines: security (a decoy engine compiled with `xcrun clang` logs every call and tries to write outside the destination: blocked for the conflict check, transfer and numbered copies, and verification cannot even write the destination; unsandboxed, the same decoy escapes, which checks the test itself), stress (3,000-file routine, 5,200 same-name files), destructive (unreadable source file, vanished listed file, Finder-locked destination file), penetration (planted links, linked destination folder, quarantine on numbered copies), load (change lines, progress flood, 100 queued jobs), volume (huge rule numbers, video sizes, an 8 EiB sparse source refused before copying), endurance (20 runs: no temporary files, no open descriptors in the workspace, no overwritten numbered copies), vulnerability (runaway regex, option-like names), red team (wildcard and backslash names, items of another type, destination inside the source, placement templates that try to leave the destination), fuzz (dry-run output, rule algebra, damaged routine files, placement templates and text dates; seeded SplitMix64) and chaos (cancel during the conflict check with an engine that ignores SIGTERM, new conflicts after a decision, parallel runs, relaunch while awaiting a decision, decisions across two sheets). Each guarantee was verified by removing it and watching its test fail.

### Pre-release stress round

```bash
./Scripts/stress-test.sh                 # core round + real app round
./Scripts/stress-test.sh --skip-app      # core round only (no accessibility permission needed)

```

Checks: the job starts by itself, pause and resume work, all files arrive, the quarantine flag is kept, the source is unchanged, the worst UI response stays under 1500 ms, VoiceOver finds a name for every control, and no crash report appears. ## Agent tooling (`.agents/` and Graphify)

Coding agents read [`.agents/AGENTS.md`](.agents/AGENTS.md) first: it holds the invariants (process boundary, sandbox, source safety, confirmed `--delete`, same-name decisions, on-device AI, archive health, localization), the workflow and a repository map. `.agents/rules/` keeps one file per adopted agent standard (index: [`.agents/rules/about_rules.md`](.agents/rules/about_rules.md)), `.agents/skills/` the test, snapshot and engine procedures, and `.agents/context/` the domain and code-graph wikis, the roadmap and the reflexion log. None of it is part of the app.

The code knowledge graph comes from [Graphify](https://github.com/Graphify-Labs/graphify) (`uv tool install graphifyy`). It is built from code only, locally and without an LLM:

```bash
GRAPHIFY_NO_TIPS=1 GRAPHIFY_QUERY_LOG_DISABLE=1 GRAPHIFY_BACKEND=off graphify extract . --code-only
GRAPHIFY_BACKEND=off graphify cluster-only . --no-label
graphify query "how does a job reach rsync?"
```

The output goes to the git-ignored `graphify-out/`. The Claude Code skill and its pre-search reminder (`CLAUDE.md`, `.claude/`) are versioned; the git hooks that refresh the graph after commits and the `graph.json` merge driver are per clone, so run `graphify hook install` once after cloning. The skill files are Apache-2.0 (see [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)); details and privacy rules are in [`.agents/rules/graphify_knowledge_graph.md`](.agents/rules/graphify_knowledge_graph.md).

## Known limitations and unverified points

- The x86_64 slices (app and rsync) build and link correctly, but could not be run on this Mac (macOS 27 without Rosetta). They should be tried on an Intel Mac.
- The real-app stress round passed on 2026-11-04 (core round and app round with Accessibility). The Finder service and drag and drop are still to be tried by hand.
- The app is ad-hoc signed and not notarized. Releases are distributed through GitHub Releases.
- Notifications: macOS 26 refuses notification permission (UNErrorDomain code 1, "Notifications are not allowed for this application") to an app opened outside `/Applications`, whatever its signature; the same ad-hoc build gets the prompt when opened from `/Applications`. Found in the hands-on round of 2026-11-04; Copiator now asks at launch and shows a banner when the permission is blocked. The Dock progress found missing in the same round was fixed by drawing the tile.
- In the installed app (2026-11-04, with an APFS disk image as the external disk): start on connect, eject when done, the old backup reminder trigger, the integrity check on connect and the menu bar icon work. Shortcuts and Siri were not driven, and no real external disk other than the user's Time Machine disk was available (Shortcuts indexes the app's actions after it is launched from `/Applications`).
