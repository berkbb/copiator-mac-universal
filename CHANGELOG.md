## [Unreleased]

### Added

- The README shows the welcome screen in English and dark mode (`docs/screenshots/welcome-dark.png`), and the installation steps explain the first-launch warning and how to remove the quarantine flag with `xattr -dr com.apple.quarantine /Applications/Copiator.app` for a copy downloaded from the Releases page.
- Developer tooling, not part of the app: a local code knowledge graph built with [Graphify](https://github.com/Graphify-Labs/graphify) from code only, offline and without an LLM (`.graphifyrc`, `.graphifyignore`, output in the git-ignored `graphify-out/`), plus the project-scoped Claude Code skill and pre-search reminder (`CLAUDE.md`, `.claude/`). The skill files keep their Apache-2.0 license; `LICENSE`, `LICENSE-MIT` and `NOTICE` sit next to them and [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) has a new "Repository-only files" section. See DEVELOPMENT.md › Agent tooling.
- **All rsync options that work inside the sandbox**, as defaults in the new **Settings › rsync** tab and per job under **Advanced rsync options** in the New Job sheet: `--filter`/`--include`/`--exclude` (one pattern per line), `-F`, `--include-from`/`--exclude-from`/`--files-from`, `--max-size`/`--min-size`, `--ignore-existing`, `--existing`, `-u`, `-m`, `-H`, `-N`, `-U`, `--numeric-ids`, `-x`, `--chmod`, `-L`/`--copy-unsafe-links`/`--safe-links`, `--sparse`, `--inplace`, `-W`, `--append`/`--append-verify`, `--delete-before/after/delay`, `--delete-excluded`, `--max-delete`, `--ignore-errors`, `--size-only`, `--modify-window`, `--bwlimit`, `--stop-after`/`--stop-at`, `--iconv`, `--link-dest`/`--compare-dest`/`--copy-dest`, `-b`/`--backup-dir`/`--suffix`, `--info=progress1`, `--info=name1`, `--info=flist2`, `--info=stats2`, `-i`, `--no-inc-recursive`, `--log-file`, `--write-batch`/`--only-write-batch`. Invalid values are explained and block the job.
- The New Job sheet and the inspector show the exact `rsync …` command (shell-quoted, copyable).
- Job rows show the file being copied, per-file progress and a counter while the file list is built; statistics and change lines go to the job log.
- A job stopped by `--stop-at`/`--stop-after` is paused (resumable) and announced instead of failing.
- **Automatic snapshots** (per job): each run writes a dated folder (`yyyy-MM-dd-HHmmss`) in the destination, hard-links unchanged files to the previous snapshot (`--link-dest`), keeps an interrupted run as `….partial` and resumes it, points `Latest` at the newest snapshot, and applies optional retention rules (keep the last N, one per day, week or month) after a fully successful run only. Retention is confirmed when it is set; only folders whose names match the snapshot format exactly are ever removed.
- **Start when the destination disk is connected** (per job): the job waits while the disk is missing and runs (again) when it is mounted. A disk that is ejected or unplugged pauses the job using it; mounting it resumes the job.
- **Verify after copying** (off, quick or checksum; default in Settings › Copying): differences or an incomplete verification end the job as "not verified" and the differences are logged.
- **Preview** in the New Job sheet: a dry run listing what will be copied, updated and deleted, with deletions highlighted.
- **Edit and duplicate** existing jobs (Job menu and context menu); **run history** with result, duration, bytes, files and snapshot per run (last 100 runs).
- **Copy routines** (sidebar › Routines, File › New Routine…, ⌥⌘N): named routines made of routes (source folder → rules → destination folder) that keep the folder structure. Finder-style rules on name, extension, folder name, relative path (contains, is, begins with, ends with, regular expression; text matching ignores case and treats Turkish I/ı/İ/i alike, regex is applied as written) and file kind, with All / Any / None and nested groups; advanced criteria (under "Advanced" in the criteria menu) for size, date modified / created / added (within the last N days/weeks/months/years, before, after), Finder tags, visibility, folder depth, extension lists, photo and video details (date taken, resolution, duration, camera model; ImageIO and AVFoundation) and text inside files (Spotlight index; no matches on unindexed volumes; I/ı/İ/i are treated alike here too, although Spotlight on a Mac set to Turkish indexes "I" as "ı"). Metadata is read only when a condition asks for it. A "Try" field tests a sample path, each route has a dry-run preview, and running a routine queues one job per route (re-runs requeue the same jobs, so their history accumulates). Rule-based jobs never delete at the destination. Routines are saved in `routines.json`, can be duplicated and deleted (their jobs stay as ordinary jobs), and appear in the menu bar and in a new "Run Copy Routine" Shortcuts action.
- **Files with the same name at the destination:** a new per-job and per-routine setting (default for new jobs in Settings › Copying) with Ask (default), Replace, Keep both (numbered copy) and Skip. With Ask, a dry run (`-n -ii`) lists every destination file with the same name before anything is copied; the job pauses as "Needs decision" (notification, menu bar entry, next jobs continue) and a sheet offers 1 · Replace, 2 · Keep Both, 3 · Skip for all files or file by file, with "Remember for this job/routine". Skipped and kept files are left out of the main transfer through a generated `--exclude-from` list; kept files are then copied under Finder-style numbered names ("report 2.xlsx"). Resuming a paused job does not ask again about files written by the same pass. Jobs and routines saved before this setting existed have "Remember" pre-checked on their first decision, so they ask only once. Snapshots, `--ignore-existing` and batch-only jobs are not checked.
- **Disk-triggered routines** now run when their destination disk is connected even if they were never run before.
- **Placement at the destination** (per route, "Placement at the destination" in the routine editor): a subfolder template such as `{year}/{month}-{monthName}` (presets for year/month name, year/month and year) and a name template such as `123456789_El_{month}_{yy}`, with the tokens `{name}`, `{folder}`, `{year}`, `{yy}`, `{month}`, `{monthName}` and `{day}`. The date comes from the date taken, the file name, the contents (PDF and text) or the modification or creation date ("Automatic" tries them in that order); month names follow the language the template was set up in; the extension is always kept; files that land on the same target are numbered. The routine editor shows an example from the Try field. Placed files keep their quarantine flag, Finder tags and other attributes; links inside packages stay links, links that point outside a package and symbolic links among the selected files are not copied (logged). Same-name questions, Keep Both, verification and resuming work on the new paths.
- **Naming modes for placement:** text before or after `{name}` in a name template is not added again when the name already has it (case and diacritics ignored), so applying a template twice keeps the name. New tokens `{targetFolder}` (the folder the file lands in) and `{targetNumber}` (the deepest number in parentheses in the destination path, e.g. `Elektrik (123456789)` → `123456789`). **Name fixes** run in order after the template: a regular expression and a replacement with `$1`, `${1}`, `$0`, `$$` and `${1:upper}`, `${1:lower}`, `${1:title}` (letter case follows the routine's language, so Turkish `i` becomes `İ`), with presets for uppercasing a leading letter-and-digit code, turning spaces into underscores and collapsing repeated underscores. Invalid expressions and unknown groups or conversions are shown as problems; an expression that runs past the step budget leaves the name unchanged. The extension is never touched.
- **Suggest a folder for each file and ask me** (per route, in Placement at the destination): before anything is copied, every selected file gets folders inside the route's destination ranked by its name and contents; the job pauses as "Needs decision" (notification, menu bar, next jobs continue) and a sheet preselects the best folder per file and offers the other suggestions, the top of the destination, a new folder or Skip, with "Rank Suggestions with AI" when the on-device model is available. Nothing is copied until Apply. "Remember" teaches the route: files with similar names (the same words and extension apart from numbers and month names) then go to that folder without asking as long as it exists; "Forget" in the routine editor clears it. The subfolder and name templates apply inside the chosen folder (`{targetNumber}` reads the chosen folder's number), the preview uses the first suggestion, and chosen or remembered folders can never leave the destination.
- **Dates found in text:** month names in Turkish, English and Romanian ("15 Ağustos 2026", "Agustos 26", "October 2026", "octombrie 2026") and numeric forms (15.08.2026, 2026-08-15, 2026 08, 08-2026, "El_10_26").
- **Text inside files without Spotlight:** PDFs (PDFKit) and plain text files are read directly when Spotlight has no match, so the criterion also works on external disks and other unindexed volumes.
- **"Copy with the same contents at the destination"** (advanced criterion, exists / does not exist): the destination is indexed by size and only same-size files are compared by contents (SHA-256), so a file already archived under another name or folder can be skipped.
- **Send to a Copiator Routine:** a new Finder service, a "Run Copy Routine on Files" Shortcuts action (usable as a Finder Quick Action) and dropping files on a routine in the sidebar run a routine on just those items: every route applies its rules and placement to them instead of its own source folder. One-off jobs are queued per folder and route; the routine's own jobs do not change.
- **Destination Overview…** (job context menu and routine detail): volume usage, file and folder counts, size per top-level folder and the five file types that take the most space.
- **Suggest a Folder…** in the routine editor: ranks the folders inside the route's destination by similarity to a file name or keyword (Turkish characters and abbreviations such as "sgrt" → "Sigorta" match, the folder's name in the contents counts too, siblings are added) and sets the chosen folder as the route's destination.
- **Move to the Trash after copying** (per job and routine, confirmed when switched on): after a successful copy, each source file whose copy at the destination has identical contents (SHA-256) goes to the Trash; files that were skipped, excluded, left behind or changed stay where they are, emptied subfolders go to the Trash too, and nothing is deleted permanently. Not available with snapshots. rsync still never gets `--remove-source-files`.
- **Clean Up Archived Sources…** (File menu and job context menu): lists the source files that already have a copy with identical contents anywhere at the destination and moves them to the Trash after confirmation.
- **Sync routines (two-way):** a routine can be a sync routine; each route compares folder A and folder B, copies files that exist on one side only to the other and asks about files that differ on both sides ("Copy A's to B", "Copy B's to A", "Skip"; rules: ask, newer wins, A wins, B wins, skip). Nothing is deleted. Rules filter both sides; one route per folder pair maps folders in different places. Each direction runs as its own sandboxed rsync job; the preview lists A → B, B → A and differing files.
- **On-device AI suggestions** (Settings › General › Artificial intelligence, **optional and off by default**; turning them on checks the prerequisites of every model that would be used — Apple Intelligence supported, turned on and downloaded; Ollama or LM Studio running on 127.0.0.1 with a local chat model and the chosen model present; and a short test question answered — lists each result with how to fix it, and stays off when no model is ready): "Rank with AI" in Suggest a Folder ranks the rule-based candidates, and "Suggest a Name Template" proposes a template from the file names already at the destination. Only the Mac's own model is used (no cloud, no Private Cloud Compute); answers are validated (only existing candidates, only known tokens) and nothing is applied without your approval. A warning next to the AI buttons and the setting says that the model works best in English and may be weaker for names in Turkish, Romanian and other languages. **Automatic** (the default model source) asks the models in a chosen order (Apple Intelligence, Ollama, LM Studio; each can be moved up or down and switched off): a model that cannot be reached, fails or gives an invalid answer is skipped silently and the next one is asked; if none answers, no error is shown and the rule-based suggestions stay. **Ollama and LM Studio** can also be chosen on their own (Settings › General › Artificial intelligence: model source and local model, with a status line and Refresh): requests go only to 127.0.0.1 (11434 or 1234), without a proxy, following no redirects; Ollama's cloud models are neither listed nor used, `<think>` sections are dropped, and answers are validated the same way. The language warning shows only while Apple Intelligence can answer. **Robust AI suggestions:** every model call is limited by a timeout and never awaited past it, and every AI action ends in one of three states: a suggestion, no valid suggestion (the rule-based suggestions stay), or "The suggestion engine is not available right now" when no model could answer, so a failing, hanging or closed model never breaks the app. **Apple Intelligence tuned for the app:** a three-language evaluation showed it choosing folders by their position in the list, so it now chooses by folder name through guided generation (the answer can only be one of the folders), without randomness, and the list is asked once more in reverse order; if the two answers differ, its suggestion is not used (Automatic moves on to the next model). Suggested name and subfolder templates must reproduce the example names at the destination, and prompts no longer contain example answers a model could copy. **Templates without AI:** "Suggest a Name Template" and "Suggest a Subfolder Template" now derive the template from the examples by rule (year, two-digit year, month, month name in Turkish, English or Romanian, day, fixed text and a varying `{name}` part; the largest group when the examples differ; year-only folders such as `Bills/2026`), work even with AI turned off, ask a model only when the rule finds nothing, and set the placement's month-name language to the examples' language. **Fit check:** when a model picks an existing folder for a file, it is asked once more whether the file really belongs there; a "no" turns the answer into a new-folder suggestion. In Automatic mode an existing folder chosen by Apple Intelligence is also checked by the next ready model; if it disagrees, that model's own decision is used. **Path suggestions:** "Suggest a Subfolder Template" proposes a template such as `{year}/{month}-{monthName}` from the folders at the destination (at least one date token, never outside the destination), and "Ask the AI" in the folder sheet reads each file's name and contents and picks the best folders or, when none fits, proposes a new folder path inside the destination (preselected, applied only with Apply).
- **Old backup reminder** (Settings › General, next to the notifications switch; default 30 days; off, 7, 14, 30, 60 or 90): when a disk is connected, and once at launch, a notification lists the jobs and routines whose destination is on that disk and that have not finished a successful run for longer than the chosen time (or never, counted from when they were created). Jobs that start on their own when the disk is connected, and jobs that are running or waiting, are left out; each item is reminded at most once a day.
- **Restore from snapshots** (job context menu › Snapshots and Restore…, for jobs with automatic snapshots): browse any snapshot folder by folder, see a file's versions over time (copies that stayed the same across snapshots are one version) and restore a file, a folder or everything to its original place or to another folder. Restoring queues an ordinary copy job, so the sandbox, the same-name question (Replace, Keep Both, Skip) and verification apply; nothing is deleted and the snapshot is only read. A missing original folder is created.
- **Archive integrity check** (Check Archive Integrity… in the job context menu and the routine detail): reads every file at the destination and compares it with a hidden list (`.copiator-integrity.json`) of sizes, dates and SHA-256 digests written by the previous check. A file whose size and date are unchanged but whose contents differ is reported as corrupted (silent disk damage) until it is fixed; files that disappeared are reported once; changed and new files are recorded; unreadable files are listed. Hard-linked snapshot copies are read once. Nothing but the list is written; a check can be stopped (the list is then left as it was), can run every time the disk is connected, and ends with a notification. rsync always leaves the list alone, so `--delete` keeps it and verification does not count it as extra.
- **Find Duplicate Files…** (job context menu and routine detail): files at the destination with identical contents (same size, then SHA-256), largest waste first. Hard links, snapshot folders, hidden files and empty files are not counted. You choose which copy stays (the shallowest by default); the others go to the Trash after confirmation, and each one is checked again just before, so a file that changed after the scan is left alone. Nothing is deleted permanently.
- **Export and import routines** (File › Export Routines…, Import Routines…; Export… in a routine's context menu): routines are saved as a versioned JSON file with their routes, rules, placement and learned folders. Imported routines get new identities (they never replace or merge with existing ones or their jobs), a name already in use gets a number, folders that do not exist on this Mac are listed and can be pointed elsewhere before importing, and files from a newer version, invalid files and files over 10 MB are refused with an explanation.
- **Repair damaged files** (Repair from Intact Copies… in the integrity sheet, confirmed): for each file the integrity check found damaged, a file with exactly the digest recorded in the integrity list is looked for at the destination (for example a separate copy in an older snapshot) and in the sources of the jobs and routes that copy there; the damaged file's contents are then rewritten in place, so snapshot copies hard-linked to it are fixed too, its date is set back to the recorded one and the result is read again and compared. Sources are only read; files that changed since the check, files without an intact copy and paths that lead outside the destination are left alone and listed.
- **Eject the destination disk when done** (per job and routine, under Automation): after a successful run the disk is ejected once no other job on it is waiting, running or waiting for a decision and no integrity check or repair is using it, so it can be unplugged safely; all volumes of that disk are checked. The job log and a notification say whether it worked. The startup disk and internal disks are never ejected.
- **Buttons in notifications:** the old backup reminder has **Back Up Now** (queues the reminded jobs and runs the routines), an integrity check with problems has **Show** (opens its sheet) and a job that needs a decision has **Decide** (opens the decision sheet). Clicking the notification itself only brings Copiator forward; the items in a notification are checked against existing jobs, routines and checked destinations before anything happens.
- **11-discipline chaos and security test matrix** (`ChaosAndSecurityMatrixTests`, `ChaosAndLoadAppTests`): security, stress, destructive, penetration, load, volume, endurance, vulnerability, red team, fuzz and chaos tests against the real rsync and the real queue, including a compiled decoy engine that tries to write outside the destination, 5,200 same-name files, an exabyte-sized sparse source, 20 repeated runs checking temporary files and open descriptors, concurrent runs and cancellation of an engine that ignores SIGTERM. Each guarantee was checked by removing it and seeing its test fail.
- **Move jobs and settings to another Mac** (File › Export Jobs and Settings…, Import Jobs and Settings…): a versioned JSON file with each job's kind, source, destination and options (no history, log, result or routine link; jobs that belong to routines are left out, since routines have their own export) and the portable settings: notifications, appearance, language, default copy options, default advanced options without file paths, verification, same-name policy, menu bar and Dock, the old backup reminder and shortcuts. The update permission, the sandbox switch, AI suggestions, a custom rsync, the integrity-on-connect list and paths that belong to the other Mac are never exported or changed. Imported jobs get new identities and arrive **paused**, so nothing runs until you start it; folders that do not exist on this Mac can be chosen again or the job left out, jobs that fail the usual checks are listed with the reason, applying the settings is optional, and other formats, newer versions and files over 10 MB are refused with an explanation.
- **Search and compare snapshots** (in Snapshots and Restore…): a search field finds files and folders by name across all of a job's snapshots (case, accents and Turkish I/ı ignored; the first 500 paths, each with the number of snapshots it is in and the newest one), and opening a result shows it in that snapshot. **Compare** lists the files added, changed and removed between two chosen snapshots (the newest two by default). Nothing is read or written: a file whose size and date (to the nanosecond) are the same counts as unchanged, hidden files are left out, and the work runs off the main thread and stops when the query or the snapshots change. **Quick Look** previews the selected file (Space) and any file in the comparison.
- **Open at login** (Settings › General): Copiator opens by itself when you log in, so jobs that start when a disk is connected, the old backup reminder and the integrity check on connect keep working after a restart. The switch reads its state from macOS (`SMAppService`), so turning it off in System Settings shows here too; when macOS waits for approval, the reason and a button to System Settings › General › Login Items & Extensions appear. Nothing is scheduled; the app only opens.
- **Clear the queue:** a **Clear** toolbar menu (also in the Job menu and the job context menu) with "Remove Finished Jobs" and "Remove All Jobs…" (confirmed; a running job stays, copied files and snapshots are not touched).
- **Ready-made exclude lists:** developer, version control, caches and macOS helper files, in Settings › rsync and per job.
- **Menu bar icon** (progress, pause/resume all, open, quit; Copiator keeps running without a window while it is shown) and **Dock progress** with a badge for pending jobs; both can be turned off in Settings › General.
- **Shortcuts and Siri:** "Run Copy Job" (choose a job), "Pause All Jobs", "Resume All Jobs", with phrases in Turkish, English and Romanian. `Scripts/build_app.sh` generates the App Intents metadata with `appintentsmetadataprocessor`.
- **Sleep and power:** the sleep assertion (`caffeinate -i` equivalent) is verified in the system's assertion list; the app tells you when it is taken and released (start, finish, pause, cancel, quit) and shows a banner while a job runs. New option "Keep the display awake during a job" (`caffeinate -d` equivalent). Power advice for battery, low battery, Low Power Mode, the lid and the display, re-checked every minute during a job.

### Fixed

- **Notifications without a Developer ID:** Copiator now asks for notification permission at launch instead of when the first notification is due. The missing permission prompt was caused by where the app was opened from, not by its ad-hoc signature: macOS refused the request ("Notifications are not allowed for this application") for the same build opened from a temporary or build folder and showed the prompt when it was opened from `/Applications`. When notifications are off, or macOS will not offer them, an orange banner at the top of the window says why and opens System Settings › Notifications, or shows Copiator in Finder so it can be moved to Applications; "Later" hides it until the next launch. It appears only while finished-job notifications, the old backup reminder or the integrity check on connect are turned on.
- **Full Disk Access when a job needs it:** a second banner asks for Full Disk Access, and opens System Settings › Privacy & Security › Full Disk Access, while Copiator does not have it and a job or routine reads or writes a folder macOS protects (Mail, Messages, Safari, Photos, the Trash, Spotlight data and similar, checked on this Mac) or covers one (the whole home folder, its Library or Pictures folder, the startup disk), or a job could not read a source because macOS refused ("Operation not permitted"). Folders the sandbox already leaves out of a larger source do not count. Access is checked by trying to open places only that permission opens, at launch and whenever Copiator comes to the front; the banner explains that after an update the switch may need to be turned off and on again. When the need arises while the window is closed (for example a job started by connecting a disk), a notification says so once per launch. The check and the banner are derived from Curatare (see THIRD_PARTY_NOTICES.md).
- **Settings › General › Permissions:** shows whether notifications and Full Disk Access are on, each with a button that opens the right System Settings page (or shows Copiator in Finder when it must be moved to Applications), so a permission can be checked and given before any job needs it.
- **Reasons in macOS permission questions:** the questions macOS asks before Copiator reads the Desktop, Documents or Downloads folder, an external or network disk, or a cloud storage folder now say why, in Turkish, English and Romanian.
- **Dock progress shows again:** while a job runs, the Dock icon now shows a bright green progress bar and the copy speed ("→ 25,5 MB/s"), drawn by the app the same way as in the sister download app; the system progress control used before never appeared in the Dock. The red number badge for pending jobs is gone (the menu bar window and the sidebar show them), and notification permission now includes the icon badge, which macOS 26 requires for an app's drawn Dock content to stay visible.
- "Check automatically when this disk is connected" no longer runs at the same moment as the jobs that start on that disk, when it could see an empty or half-written destination; it now waits until the disk's waiting, running and decision-waiting jobs are done, and "eject when done" waits for the check.
- Developer tooling: the stress round's accessibility probe skipped every outline, including Copiator's job list, so it could not find the pause/resume button; it now searches the job list and the full round passes (20,000 files and a 2 GB file, pause and resume, quarantine kept, worst UI response 64 ms, VoiceOver labels).
- **A placement template could leave the destination:** a value such as ". .." became ".." after its leading dot was trimmed once. Names are now trimmed until they stop changing, and a staged path with "." or ".." is never created (found by the new placement fuzz test).
- **A folder arriving where a file with the same name exists** at the destination made rsync delete that file without asking (likewise an incoming file over an empty folder or a link). These now count as same-name items and are asked about; Keep Both renames the existing item with a number ("belgeler 2") so the folder keeps its place in the structure.
- **Skipped files whose name contains a backslash** but no `*`, `?` or `[` were replaced anyway: rsync compares such patterns literally, so the escaped backslash never matched. Patterns are now escaped as a whole, and only when they contain wildcards.
- **A runaway regular expression** in a routine rule (for example `(a+)+$`) froze the scan, could not be cancelled, and froze the routine editor's Try field. Matching now stops at a fixed step budget; the job fails with an explanation and the Try field shows that the expression is too complex.
- **"Within the last N days/weeks/months/years" with a very large N** crashed the app.
- **Keep Both copies of downloaded files** lost the quarantine flag with macOS's rsync or when extended attributes are not copied.
- **The same-name sheet** listed files that were already decided, and a second sheet dropped the first sheet's decisions. Only undecided files are listed now and decisions add up.
- **A listed file that vanished before the copy** made the job report "The source could not be found" although the other files were copied; it now reports that some source files were deleted or moved.
- **Lost command output under load:** pipes were drained by blocking jobs on the shared GCD pool; with many processes at once a reader could start only after the 2-second grace period that follows process exit, and the output was lost. Each pipe now has its own reader thread.
- **The opt-in stress test** stopped at "Needs decision" after its cancel-and-resume step; it now cancels once copying has started and applies the run's events as the app does.
- **Crash when a job starts:** adding a job (for example the first one, from the New Job sheet) could terminate the app with "more Update Constraints in Window passes than there are views in the window". The sleep and power banner above the job list wrapped its text, so its height depended on the column width and the split view recomputed its layout in a loop. The banner above the list is now one line per item (full text in the tooltip); the inspector still shows it wrapped.
- **macOS's own rsync (limited mode) works again under the sandbox:** openrsync starts its receiving side as a separate `rsync` found through `PATH`; with another rsync earlier in `PATH` (e.g. Homebrew's) the sandbox refused it ("exec on 'rsync': Operation not permitted"). Copiator now passes `--rsync-path` with the engine's own path, does not ask openrsync to copy extended attributes (it writes temporary AppleDouble files to `/private/tmp` and breaks dry runs; the quarantine flag is still carried over and the dropped option is logged), and reads openrsync's 9-column `-i` output for verify, preview and the change log.
- **No orphaned rsync after a crash:** child processes are recorded; on a crash or termination signal Copiator stops them before exiting, and an rsync left running by a killed session (matched by process ID, exact start time and a dead parent) is stopped at the next launch and noted in the interrupted job's log.

### Security

- **The rsync sandbox fails closed:** when `/usr/bin/sandbox-exec` is missing, a job, preview or verification that uses the sandbox is refused with a clear message ("rsync was not started because sandbox-exec is missing…") instead of running rsync unprotected, in Turkish, English and Romanian. Settings › Advanced shows a warning in that case and keeps the sandbox switch usable, so running without the sandbox is only ever the user's own choice. Previously rsync silently ran without the sandbox.
- Extra sandbox permissions are granted per job only for paths you choose: list files (read), log and batch files (write that file), an outside old-versions folder and the `--link-dest` previous backup (write). Paths inside the source are refused. List files in protected folders are read by the app and passed to rsync as a private temporary copy, so the protected folder stays closed.

## [1.0.0] — 2026-10-21

First release: local disk to local disk backup and sync with rsync.

### Added

- **Job queue** in the style of Transmission: source, destination, options, status (waiting, scanning, copying, paused, finished, failed), progress bar, bytes copied, speed, time left, checked items and a per-job log. Jobs run one at a time in list order, can be reordered, paused, resumed, run again and removed; the whole queue can be held. Sidebar filters with counts and a detail inspector.
- **Resume:** an interrupted, paused or failed job continues with the same rsync command (`--partial`). Jobs are saved to `~/Library/Application Support/Copiator/jobs.json`; after a quit or crash during a copy the job comes back paused and marked as interrupted (optionally resumed at launch).
- **Verify:** dry run of the job (`-n -i`, optionally with checksums `-c`) listing missing, changed, extra and attribute-only differences; nothing is written.
- **Copy mode:** copy the folder itself or its contents, with a preview of where the copy lands.
- **Options:** keep permissions, owner and ACLs (`-pogA`); keep extended attributes (`-X`); leave out macOS system folders (`.Spotlight-V100`, `.TemporaryItems`, `.Trashes`, `.fseventsd`, …); delete extra files at the destination (`--delete`, only when chosen and confirmed). Defaults for new jobs in Settings › Copying.
- **exFAT/FAT/NTFS destinations:** no permission flags, harmless attribute warnings shown as one line, `--modify-window=1` on FAT.
- **Bundled rsync 3.5.1**, universal and linked only to macOS system libraries, built from the official `v3.5.1` tag by `Scripts/build-rsync.sh`; source, commit, flags and SHA-256 in `Vendor/rsync/SOURCE.txt`.
- **Engine selection** between the bundled rsync, an updated copy, Homebrew, a custom rsync and (last resort, limited progress) macOS's own rsync.
- **rsync updater** (`Scripts/update-rsync.sh`, "Check for rsync Updates…", `rsync-Guncelle.command`): GitHub release check, SHA-256 verified source download, local universal build, Mach-O and version checks, atomic install, fallback folder when the app bundle is read-only.
- Idle sleep is prevented while a job runs; a notification arrives when a job finishes or fails.
- Finder service "Back Up with Copiator" and drag and drop onto the window.
- Turkish (default), English and Romanian, 1:1; Automatic, Light and Dark appearance; customizable shortcuts.
- About window with Copiator License, rsync License and Third-Party Notices shown read-only inside the app.
- Copiator update check through GitHub Releases (asked for on first launch), Ed25519-signed DMGs and SHA-256 checksums.

### Security

- rsync runs under `sandbox-exec`: no network, writes only to the destination, sources read-only even inside the destination, no other programs or mach services, personal-data folders (`~/.ssh`, Keychains, browser profiles, …) unreadable unless chosen as the source and excluded from larger sources. Verify runs without any writable folder.
- The source is never modified: `--remove-source-files` is never produced, and jobs whose source and destination overlap are refused.
- Free space is checked before copying and watched while copying; the copy stops before the destination fills up.
- The quarantine flag of downloaded files is carried to copies even when extended attributes are not copied.
- Error classes are recognized only at rsync's message position or errno text, so file names cannot fake an error class.
